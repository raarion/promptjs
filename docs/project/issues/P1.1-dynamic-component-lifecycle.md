# P1.1 — Dynamic component lifecycle after SPA mount

**Status**: Open / tracker issue  
**Priority**: P1.1  
**Scope**: Architecture design + runtime/compiler implementation  
**Created**: 2026-07-07 during the v132 clean-gate follow-up

## Problem

Dynamic component instances created after the initial SPA page mount do not have
an instance-level contract that guarantees their `dipasang:` lifecycle hook runs
when the component's root DOM is actually attached.

The existing lifecycle model is page-oriented: `dipasang:`/`dilepas:` hooks are
wired into the SPA page factory mount/unmount flow. That works for the initial
page lifecycle, but it does not fully model component instances that are created
later from dynamic paths such as reactive rerenders, conditional branches, or
lists.

## Why this needs a tracker

This is not just a line item in the v132 stabilization report. It is a real
architecture gap because the system needs a deliberate instance-lifecycle model:

- where component instance cleanup ownership lives;
- when a dynamic component can be considered attached to the DOM;
- whether `dipasang:` should be triggered by caller-side attach points,
  `MutationObserver`, or a compiler/runtime contract;
- how `dilepas:` composes with existing `registerCleanup()` and keyed-list
  per-item cleanup.

## Acceptance criteria

- Dynamic component instances created after SPA mount have deterministic
  `dipasang:` timing.
- Dynamic component instances run `dilepas:`/cleanup exactly once when removed.
- The design works for conditional rendering, `Saat` rerenders, plain lists, and
  keyed lists.
- The implementation has regression tests covering at least one dynamically
  inserted component and one removed component.
- The docs explain the timing contract and any deliberate limitations.

## Candidate designs to evaluate

1. **Caller-side attach contract** — compiler/runtime calls the component's mount
   hook at the exact site that appends/inserts its root node.
2. **MutationObserver-backed attach detection** — runtime observes attachment and
   calls hooks when the component root becomes connected.
3. **Deferred design** — keep page-level lifecycle only, but document component
   lifecycle as initial-mount-only until a later runtime pass.

Option 1 is likely the lowest-overhead runtime path, but it requires a clear
contract between component factories and every DOM insertion site.
