## S2-BUG-1 — `kurangi <n> dari <t>` mis-mapped target/value

**Repro (real codegen, before):**
```
Kurangi 1 dari hitung  →  __setState(document, 1 - 1);        // ❌ target=document, literal
Kurangi n dari hitung  →  __setState(n, n.value - 1);          // ❌ target=n(!), dropped `dari`
```
**Root cause:** statement-position `kurangi`/`tambahkan` dispatch to
`_parseSimpanStatement` (`src/parser/promptjs-parser.js:290`). That function only
knew `kurangi <target> [ke <value>]` — it never handled the **documented**
value-first `dari` form (`docs/language/syntax-reference.md:166`). So the first
expression (the value) became the target and `dari <target>` was silently
dropped; `resolveTarget(<numeric literal>)` falls back to `document`.

**Fix (`promptjs-parser.js`, `_parseSimpanStatement`):** parse the first
expression, then if `dari`/`from`/`in` (TK_IN) follows, treat the first expr as
the VALUE and the expr after `dari` as the TARGET (mirrors the inline-expression
path already at ~line 1516). Otherwise the first expr is the target (`kurangi
<t>` decrement / `kurangi <t> ke <v>`).

**After:**
```
kurangi 1 dari hitung  →  __setState(hitung, hitung.value - 1);       // ✅
kurangi n dari hitung  →  __setState(hitung, hitung.value - n.value); // ✅
kurangi hitung         →  __setState(hitung, hitung.value - 1);       // ✅ (unchanged)
kurangi hitung ke 5    →  __setState(hitung, hitung.value - 5);       // ✅ (target-first)
```

## S2-BUG-1c (derived) — reactive-scalar `tambahkan` dropped `.value`

**Repro (before):** `tambahkan 3 ke hitung` → `__setState(hitung, hitung + 3);`.
`hitung` is a reactive Proxy → `hitung + 3` coerces to `"[object Object]3"` at
runtime. Silent-wrong, same danger class as BUG-1.

**Root cause:** `visitTambahkanStatement` (`src/compiler/emitters/statements.js`)
built the read side from `resolveTarget()` output (`hitung`) without unwrapping.
`resolveTarget` only appends `.value` when `node.target.resolved.kind` is set,
but the resolver attaches reactivity via `targetSymbol` on the statement, not
`resolved` on the identifier.

**Fix:** in the reactive-scalar branch, read as `<stateName>.value` (matching the
`__setState` write side and mirroring `visitKurangiStatement`). Array-target
`tambahkan` still uses the push+spread path (asserted).
**After:** `__setState(hitung, hitung.value + 3);`

## S2-INK-1 — self-referential `turunan` cycle passed silently

**Repro (before):** `turunan c = c tambah a` → `success:true`, **no E4201**.
**Root cause:** `buildDependencyGraph` (`src/analyzer/dependency-graph.js`)
discarded self edges with `if (… || ref.symbol.id === sym.id) return;`, so the
`c → c` edge never reached `detectCycles` (whose DFS *does* handle self-loops).

**Fix:** remove the self-edge guard; record the `c → c` edge (deduplicated so a
symbol referenced N times yields one edge). `detectCycles` then reports the loop.
**After:** `turunan c = c tambah a` → `success:false`, **E4201** `Dependency
cycle pada data turunan: c -> c`. `c = c + c` → exactly one E4201 (dedup).
Non-cyclic chains (`c=a+1; d=c+1`) stay clean — no false positive.

## S2-DX-1 — `tampilkan "<selector>"` footgun

**Repro:** `tampilkan "#box"` → `alert("#box")` (string = message), while
`sembunyikan/kosongkan "#box"` operate on the ELEMENT. Silent asymmetry.
**Fix:** new **W3005** (registered in `error-codes.js`) emitted by the analyzer's
`visitTampilkanStatement` when the target is a bare string literal that looks like
a CSS selector (`^\s*[#.][\w-]`), only for the plain message form (no
`mountTarget`/`mode`). Non-fatal (`success` stays true). A real message
(`"Halo dunia"`) does NOT warn; element ops are untouched.

## Known gaps / not fixed (honest disclosure)

1. **`kurangi <value> ke <target>` (value-first `ke`)** still mis-targets:
   `kurangi 5 ke hitung` → `__setState(document, 5 - hitung.value)`. This form is
   **undocumented** (only the target-first `kurangi <t> ke <v>` and the value-first
   `dari` form are specified). Not fixed to avoid changing an unspecified grammar;
   the two documented forms are correct. Candidate: reject a numeric-literal target
   with a diagnostic.
2. **Mutual forward-ref cycles** (`turunan d = c…; turunan c = d…`) still surface as
   **E3001** (resolver forward-ref guard) before the analyzer's E4201. Not silent
   (a diagnostic IS raised), but the code differs. Fixing needs `turunan` hoisting
   before init-resolution — larger change, deferred.
3. **`Gunakan Nama(prop: val)`** props-parenthesis syntax is unimplemented (E3001).
   Either implement prop-parsing (+ a dedicated E2025) or align docs/examples to the
   only working form `Gunakan Nama attr="val"`.
